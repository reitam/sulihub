# SuliHub v2.8.0 – Release notes

| | |
|---|---|
| **Verzió** | `v2.8.0` |

## Kiadás összefoglalója

- **Publikus repository** – a SuliHub forráskódja nyilvánosan elérhető
- **Tiszta history** – személyes adatok, munkahelyi e-mail és belső útvonalak nélkül
- **Publikus dokumentáció + quick start** – Docker Compose, `./data` / `./backup` alapokkal
- **Biztonság és hozzájárulás** – SECURITY, CONTRIBUTING, Code of Conduct, issue/PR sablonok
- **Függőség-audit** – 0 ismert sebezhetőség; `pip-audit` a CI-ban + heti Dependabot

## Változások

### Publikus repository

- A repo **2026-11-27-től public**: https://github.com/reitam/sulihub
- Description/topics, secret scanning + push protection, Dependabot security
  updates, privát sebezhetőség-bejelentés, Actions default read-only.
- Projects/Wiki/Discussions kikapcsolva; a publikus backlog GitHub Issues/Projects.

### History és adatvédelem

- A publikus kiadás előtt a git history **újraírva**: minden author/committer a
  publikus Gmail-címen; a valódi tanárnevek, iskolai azonosítók és belső
  szerver-/útvonal-hivatkozások eltávolítva.
- A `deploy.ps1`, `backup/`, `poc/`, `docs/osszefoglalo/`, `tools/kaneo_ticket.py`
  és a régi `OSSZEFOGLALO-*.md` fájlok a historyból is kikerültek.
- A belső üzemeltetési/deploy dokumentáció és a Kaneo-eszköz a privát
  `sulihub_devops` repóba került.
- A rewrite előtti teljes backup a sikeres ellenőrzés után törölve.

### Docker / quick start

- `docker-compose.yml`: a `DATA_DIR` / `BACKUP_DIR` alapértéke **`./data`** és
  **`./backup`** (a korábbi szerver-specifikus `/mnt/...` helyett).
- A `.env` **nem kötelező**; a Compose a `.env`-et interpolációhoz betölti, az
  `NTFY_*` / `APP_ENVIRONMENT` változók defaulttal is mennek.
- README quick start: `git clone` → `mkdir -p data backup` →
  `cp config.json.example data/config.json` → `docker compose up -d --build`.
- Linuxos kötet-jogosultság tipp (`chown 1000:1000`) és a `DATA_DIR`/`BACKUP_DIR`
  felülírás dokumentálva.

### Biztonság és hozzájárulás

- `SECURITY.md` (privát sebezhetőség-bejelentés, adatvédelmi figyelmeztetés),
  `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`.
- Issue-sablonok (hiba/funkció) és PR-sablon; README badge-ek (CI/licenc/release).
- A publikus docs nem tartalmaz HPReiTam/Samba/SSH/IP vagy privát devops hivatkozást;
  a Kaneo-ticketszámok történeti hivatkozásként, magyarázattal szerepelnek.

### Függőségek

- OSV.dev audit (2026-11-27): a `requirements.txt` felső korlátján belüli legfrissebb
  PyPI-verziók és a vendorolt frontend-könyvtárak (Bootstrap 5.3.0, DataTables
  1.13.6 + Responsive 2.5.0, jQuery 3.7.0, FullCalendar 6.1.8, Font Awesome 6.4.0)
  esetében **0 ismert sebezhetőség**.
- Új CI job: `pip-audit`; új `.github/dependabot.yml` (pip + GitHub Actions, heti).
- A `kreta_api.py` `API_KEY`-e dokumentáltan nyilvános klienskulcs (nem felhasználói titok).

### Üzemeltetés

- **Fontos deploy-fix:** a publikus compose `./data` / `./backup` defaultja miatt a
  privát `deploy.ps1` a szerver `.env`-jébe írja a valós `DATA_DIR` / `BACKUP_DIR`
  értékeket, így a meglévő kötetek (`/mnt/Maxxel_HDD/...`) megmaradnak.
- A v2.8.0-ban **nincs alkalmazásfunkció-változás** a v2.7.8-hoz képest; a
  mobil/üzenet javítások már a v2.7.8-ban élesben vannak.

## Tesztek

## Élesítés


- `/health` = `v2.8.0`, a konténer `healthy`;
- a meglévő adat/mentés kötet megmaradt (a szerver `.env`-jében a `DATA_DIR` /
  `BACKUP_DIR` a régi útvonalakra mutat);
- a publikus README/badge-ek a v2.8.0-t mutatják;
- a GitHub Release a tag push után automatikusan létrejön.
